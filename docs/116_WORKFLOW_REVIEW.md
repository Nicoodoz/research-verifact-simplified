# 116自主研究周期：工作方式、产出与流程复盘

记录日期：2026-10-29。本文件复盘116实际发生的工作，不启动新实验。数值以[结果报告](../outputs/116_research_cycle/report.md)、[全部比较](../outputs/116_research_cycle/comparison.jsonl)和[周期状态](../outputs/116_research_cycle/cycle_state.json)为准。

## 结论

这次流程完成了六个候选的真实筛查、两次有限训练、必要扩展和归档，但**没有找到足以替代107 label_only的改进**。最好的开发点估计来自claim_repeat：1817条MCC提高0.00730、正确数增加7、false-S增加1，尚不稳定，也没有达到本周期主要目标。

工程执行和费用控制总体有效；科研选题与筛查顺序仍有问题。尤其是：部分结果主要表现为类别倾向变化，未证实稳定改善了临床关系判断；反复使用同一小面板容易放大偶然改善；一个廉价读出检查做得偏晚。不能把“运行顺畅、梯度正常、及时推送”当成方法有效。

## 实际工作方式

授权是一个最长12小时的自主周期，而不是每个编号结束就等待下一次批准。预算统一累计：现有32GB实例1.58元/小时，GPU与收费API各上限20元。没有另租实例、重装环境或下载一份新9B底座。

我作为主执行者管理唯一GPU队列、判断候选去留、维护状态和推送。子代理只并行做方法质疑、数据交集核查和实现复核，没有另起GPU训练。CPU统计、备份、文档和发布尽量与GPU工作并行；两个训练候选的完整状态在评价期间回传。

实际流程是：

1. 读取已有结果和缓存，写下假设、固定配置与粗筛条件。
2. 优先做原103的自然120／压力60真实分类，复用107预测。
3. 有信号时补齐旧自然400／压力100；只推缺失430条。
4. claim_repeat继续补1207条，得到同一选型20人的完整1817条。
5. 阴性候选停止；全部首次回执、失败结果和训练状态保留。

这里并不是严格嵌套的“180→500→1817”：**原180与旧500只重合70条，面板定义也不同**。因此，一个候选覆盖两者实际需要610次预测。这个事实后来成为解释小面板改善为何没有延续的重要依据。

训练仍只用原40名训练患者，选型20人没有回填训练。single_token的内部验证另从训练40人中隔出8人。后续确认40人没有用于本周期选方法或确认；没有升级默认系统。

## 流程做对的地方

第一，缓存复用确实减少了成本。没有为了形式一致重训107，没有重新推已有完整基线，也没有先给所有候选补齐1817条。候选扩大时按ID补缺，未因结果不好重发。

第二，工程验证与效果判断分开。真实显存、梯度、恢复和学习率检查用于确认实现；候选去留依据真实分类、false-S及S／NS／NA得失。训练loss下降没有被写成分类收益。

第三，失败没有被藏起来。短训练的小面板阳性、扩大后的阴性、support_check的边界放行理由、训练预算修改和全部结果都保留。没有读取确认40人来寻找更好看的结论。

第四，GPU与CPU尽量并行，最终状态完整回传；发现没有值得继续的对象后，提前收束，没有为了用完12小时或20元继续堆尝试。

## 流程存在的问题

### 1. 小面板承担了过多筛选任务

同一180条被多个候选反复用于开发选择，并不构成多次独立验证。它与500仅重合70条、自然／压力归属也会变化，早期改善很容易依赖少数患者和具体样本。没有把评价样本用于梯度训练，并不意味着不存在开发选择偏倚。

后续若另开周期，应预先从现有500中固定一个按患者、标签、来源和长度覆盖的嵌套粗筛子集，复用基线，并对全部候选统一使用。不能看到哪个子集好看再选它；本周期历史面板及结果不改写。

### 2. 廉价检查的顺序偏晚

冻结107的三代码读出仅花约6分钟，却是在约24分钟新训练及其扩大评价之后才做。它更早出现，可以提示“读出方式本身也会改变风险”，帮助判断是否值得投入训练工程。

但它不是训练方案的充分反证：未经该目标训练的读出失败，不能证明训练后必然失败。正确改进是把它作为早期诊断，而不是拿它机械否决所有判别训练。

### 3. 停止规则有过边界放宽

support_check在180条只净多3条正确，未达到原先写下的+4条件。我根据两面板MCC方向为正、false-S未增和扩展便宜，仍决定补500，并明确记录为边界判断。它不属于通过原规则，最终也没有形成收益。

这个决定在用户允许宽松探索的范围内，但体现了我对弱信号偏乐观。更好的办法是事先限定一次边界扩展的理由和最高成本，避免每次差一点都例外放行。不能事后把准入规则改成恰好通过。

### 4. 候选多，不等于获得了更多有效监督

路径评分、三代码读出和提示核对主要改变决策形式或类别倾向。它们没有直接补充“某个临床关系在当前reference中是否成立”的可靠监督。多次出现NS救回伴随NA损失，说明继续换接口或轻微调参的依据已经减弱。

对已有资料的核查也没有发现一批遗漏的、可直接扩大的新高质量三类集合：3675池中的196条`gt_explained`就是107原训练集；历史索引另有78条未决、14条`reference_gap`、3387条未审。single_token建池实际排除15条已确认输入缺证，包含额外确认的1条，不能将它与历史索引的14条混为一谈。两个106候选各有34条已解释，且均来自旧196。**未审不等于坏标签**，更大原GT数据量仍是没有充分验证的假设；但不能把“有更多行”说成“有更多经过证据核对的困难样本”。

### 5. 沟通与状态维护可以更简洁

实时进度、恢复状态和双仓库归档有用，但频繁进度播报、多个阶段名称和重复表格增加了阅读负担。部分“当前”说明也曾落后于实际任务，需要人工同步。最终已将主表集中到一份报告，重复基线合并，原始结果仍保留。

后续应以一个状态文件、一份集中报告和事件式解释为主；进度文档自动更新，聊天突出任务切换、ETA明显变化和真正的分类结果。提交次数和报告页数不是科研产出指标。

### 6. 时间优先与训练充分性之间，判断还不够好

single_token在原计划96步中只跑了24步，且内部验证最终选中第24步。这可以支持“当前24步检查点在500条上没有综合收益”，却不足以判断继续训练已经没有价值，也不能证明三类判别训练这条路线无效。提前止损有节省时间的收益，也有错过尚未学好的候选的代价；只强调前者，会把短训筛查变成对方法的过早否决。

同样，116在约3小时后收束，远早于12小时授权上限。不为用完预算而延长是合理的，但六个小改动阴性，不等于可用研究方向已经耗尽。对完整训练池、可学习判别头等实质不同的假设，当时并没有充分效果证据。我的不足在于没有把“已有配方应停止”与“研究目标是否仍值得继续投入”分开判断，也没有充分衡量一次更完整训练相对于反复切换小候选的价值。

后续应在启动前写清最小合理训练量，并结合训练集拟合、内部患者验证趋势和实际吞吐决定是否延长；开发集仍负责判断实际收益，不能边看成绩边无限追加。内部验证末点最好不等于必须继续训练，但需要有具体理由才能认为训练已经充分。未审的原医生GT样本也不能仅因未人工复核而一律排除。

## 下一轮应该怎样调整

更合理的顺序是：先把历史证据和仍未解决的具体错误写清楚，选一个能带来新信息的主要假设；先做与该假设直接相关的廉价诊断；再用固定嵌套粗筛决定是否扩大。明确类别损失和成本上限，失败后检查是否仍有不同依据，而不是立刻改一个参数继续。

116暴露的问题之一，是现有尝试很少直接改善断言与证据关系的学习。因此值得评估能带来新学习信号的方案，但不能把新增人工监督当作继续研究的前提。扩大既有原GT训练资料、学习合适的判别头，或者给予已有候选有依据的充分训练，也都是116尚未排除的方向。原文关系核对可帮助解释错误，不应变成每次效果筛查前的全量审计，更不能让模型改写医生GT。

本周期的决定是保留107，claim_repeat仅作为未确认的小幅辅助结果，不消耗确认40人的机会。116给出的主要成果是缩小了可行方向和保存了可复用工程，**没有完成性能提升目标**；下一轮仍须靠新的真实分类收益证明价值。
