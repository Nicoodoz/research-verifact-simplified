# 硅基流动多账号自动切换

现行约定（2026-09-23）：硅基流动用于Pro BGE embedding/reranker，优先复用冻结缓存；DeepSeek/Qwen Judge直接阿里云，不等待本号池耗尽。新任务默认全任务累计20元，技术故障在预算内有限重试恢复，成功回答不重发。详见[API政策](../API_POLICY.md)与[研究执行原则](../RESEARCH_EXECUTION.md)。下列通用Runner的历史功能不等于新任务已自动具备最新恢复能力。

已实现供后续任务使用的独立执行入口。按编号使用账号，收到明确且没有答案的余额不足回执后，自动切换下一个账号并重发同一请求。004 原执行/重放代码、原始回执及审计材料均未修改。工具初次交付时仅做虚构离线测试。其后009已保存account_1无答案402后转account_2成功的真实记录，见[009已审结果](../../outputs/009_retrieval_baselines/README.md)。这不代表已验证所有错误恢复路径或当前账号余额。最近016的硅基流动调用来自account_2；尚无全号池耗尽证据。

**你只需在仓库根目录的 `.env.siliconflow_pool` 填入 key。** 这是本地凭据文件，本文不声明其当前是否为空；每行一个不同账号的 key，放在等号右边：

```dotenv
# SILICONFLOW_API_KEY_1=已停用，保留本地原值，不启用
SILICONFLOW_API_KEY_2=第二个账号的key
SILICONFLOW_API_KEY_3=第三个账号的key
```

这些是填写示意，不是真实 key。无需引号，不要加行尾注释。用不到的行保持空白；更多账号继续加 `_4`、`_5` 等，按数字顺序读取。已有 `.env` 和 `SILICONFLOW_API_KEY` 不改动；新入口只读取编号变量。进程环境中的同名非空变量优先于文件。不要把 key 发到聊天或写进其他文件。

该文件已被现有 `.gitignore` 的 `.env.*` 规则排除，本次未修改 .gitignore。可提交的空模板是 [keys.env.example](keys.env.example)，不能在模板中填写真实 key。

填完后，在项目根目录、统一启动器执行：

```powershell
pwsh -NoProfile -File scripts/run_research.ps1 scripts/run_siliconflow_pool.py check-keys
```

只显示配置数量和 `account_1` 等别名，不显示密钥，也不请求接口或查询余额。这项检查只能确认本地配置格式，不能证明 key 有效或当前账号余额。无需每个请求都查询余额；切换依据是实际无答案的 `HTTP 402 / code 30001`。

下列运行命令、固定预算预留和遇429暂停的行为专指通用多账号Runner。006–013的收费任务复用账号读取或传输功能，但各有冻结的计费/重试执行器；012为纯离线分析。尤其013按一个任务锁累计所有阶段费用和未知预留，再从共同40元上限扣减，不能将阶段上限相加当新授权；后续新任务采用20元现行门槛，历史任务原上限记录不变。历史任务均已结束，勿混用恢复命令或直接续跑；具体行为以对应任务协议为准。后续符合[当前API费用规则](../../AGENTS.md#api-调用费用与确认规则)的任务可按已登记方案使用通用 [执行入口](../../scripts/run_siliconflow_pool.py) 运行，核心为 [siliconflow_pool.py](../../src/verifact_research/inference/siliconflow_pool.py)。旧 004 入口不会自动改用多账号，也不应拿旧 004 再试。每个新任务先保存 JSONL 请求清单，每行包含 `request_id`、原生聊天请求 `body`、`max_cost_cny`（单次调用预算上界）。不对命题作新切分或改变模型输入；此模块只负责服务调度和保存回执，不判定医学标签。评价仍须走项目的统一入口。

运行命令参数为 `run --requests <新任务清单.jsonl> --output <outputs下的新目录> --budget-cny <本任务总上限> --workers <并发数> --max-attempts <每请求总尝试上限>`。默认串行、每请求最多 5 次尝试，切换账号也计入同一尝试上限；账号较多时在新任务开始前显式设置足够的上限。CLI 禁止输出到 004 目录。相同参数再次运行会验证清单和原回执，并接着完成未完成请求。

执行规则与边界：

- 每次尝试记录账号别名、请求指纹和回执，所有线程共享账号状态；仅耗尽的那个账号会被停用。已在途的请求正常收尾，不重发成功回答。
- 200 响应即保存为“已收到回答”；即使回答截断或格式不对，也不通过换 key 重生成。是否为有效研究预测由后续解析和统一评价决定。
- 429、401/403 等其他服务错误会暂停本次派发，保留回执，不冒充余额不足切换。该旧Runner对超时/崩溃未知结果保留预算并要求人工核查，这是历史实现限制；新任务应按现行原则在任务层保留未知预留、有限重试并恢复，不把该限制当通用审批要求。
- 这个旧通用Runner在所有账号耗尽时暂停并保留进度；它本身没有跨平台调度器。019–021旧规则曾要求全池耗尽后迁往阿里云；现行Judge已经直连阿里云，BGE若需切平台须先核对可用服务和冻结条件，不静默替换。只有用户明确要求恢复硅基流动时，才在原列表末尾追加账号并恢复；不要删除、改名或调整既有账号顺序，也不要在任务中把某个别名换成另一账号。同一运行状态里已标记耗尽的账号不会因恢复自动启用；旧Runner自身没有全项目永久停用开关；新任务须先读取并遵守全平台迁移登记，不能因此重新尝试已耗尽号池。新增key在下次启动/恢复时加载，运行进程不会即时重读。
- 总预算不会因为换账号或重启而归零。执行器保守累计每次发送前声明的 `max_cost_cny`；只有明确无答案的余额错误会释放这次预算占用。`reserved_budget_cny` **不是实际费用、余额或账单**，这可能使任务比实际余额耗尽更早暂停。单次上界及任务上限需在下次实验准备时明确；本模块不假定某个永久不变的模型价格，也不把“每个账号 16 元”直接当作任务预算。
- 工作目录中的 `manifest.json` 固定输入、预算及代码版本；`state.json` 保存进度；`receipt_*.json` 保留尝试记录。不要手工改这些文件来重跑答案。发现残留 `runner.lock` 时先核实其中 PID 对应进程已退出，再处理锁，不自动删除活动锁。

离线自查命令：`python -B -m unittest discover -s tests -p test_siliconflow_pool.py -v`。覆盖余额切换、并发迟到回执、账号全耗尽后追加恢复、预算/重试上限、失败保护、崩溃恢复、凭据隐藏和输入/回执变更拒绝。完整验证记录见 [verification.json](../../outputs/service_tools/siliconflow_pool/verification_001/verification.json)。按071更新后的长期授权，一次新任务收费API累计总费用不超过20元（含20元）可登记执行；超过20元或无法合理估算时先确认。费用按整个任务跨账号、供应商和阶段累计，包含收费预检及必要重试／补跑，不能按 key 或批次拆开计算。执行前记录用途、范围、估算与上限；无另行指定预算时自动执行上限设为20元，若后续发送将使任务累计预计超过上限，先暂停新增收费请求并确认。历史 run 的授权和预算保持原记录。
