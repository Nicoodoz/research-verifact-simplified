## 四、实现一个有限预算的全局集合选择器，别暴力穷举API

交付一个独立可复用的实现：候选池输入 → 集合提议 → 请求/缓存 → V上真实效用 → 有限搜索 → 唯一冻结D*。

### 推荐首轮原型

使用**完整四例组的有界搜索**，而不是逐个示例单独评分后直接相加。可以采用原F4或一个事前代表性组作为起点，在保持类别、患者、长度约束下进行单槽替换，配合少量事前固定的分层随机组。最多测试多少个不同集合、允许多少轮、如何产生提议，都在搜索前登记。

具体实现由你根据预算决定，首轮可以只实测约4–6个不同完整集合。应始终包含F4、不使用效用的分层随机对照，以及预算允许的简单代表性/多样性对照。不要启动大模型训练、强化学习或需要内部梯度的算法。

关键要求：

1. **集合效用必须来自真实完整prompt调用。** 单例有效不保证组合有效；未调用的组合只能标记未测，不用加和估计伪造成绩。
2. 搜索阶段不同集合尽量作用于同一批V病例，采用配对比较，避免各组分母不同。
3. 不只搜索“能救回F4错误的病例”，也计入原正确病例的损失。
4. 缓存键覆盖目标claim、reference、完整有序示例、所有提示/参数、模型和解析版本。不同示例组即使标签相同也不能错用缓存。
5. 同一完整请求重复出现在搜索/对照时，共享它的既定主回答；不得当作两个独立实验。
6. 不根据E成绩选示例、换起点、调整搜索次数或选算法。
7. 选择可以返回原F4，甚至得出“本次未找到超过F4的新组”；这是合法研究结果。

### 选择目标与风险口径

默认以V上固定PriorG后的**MCC为主要选择指标**，同时记录PA、Macro-F1、三类召回、错误支持及逐患者效应。可以用患者等权PA、较低错误支持、较短输入依次作预设平手规则。选参/平手规则须事先固定。

不要只按整体准确率或加权NLL选择，重演083“NS已经不预测却仍被认为良好”的问题。也不要自行发明一个声称代表用户偏好的风险惩罚系数。

**不沿用084的3个百分点风险硬线，不要求所有指标同时改善。** 允许整体性能改善伴随小幅错误支持增加。报告所增加的数量、两个有明确分母的比例及类别损失；用户对084的接受不等于对任意代价的预授权。

如果V中类别不足导致MCC无法计算，按预先规定的合理备用指标处理并注明；不能看到结果后更换指标。若出现NS/NA几乎不预测，明确标记严重代价，不包装成084那种小幅取舍。

### 有用的离线工作

利用真实V效用表作患者留一排名稳定性、固定搜索预算下的随机/代表性比较、入选频率和成本分析。不要把重抽同一张表当成重新进行独立API实验。

如果随机搜索在同等实测预算下已经一样好，应该明确说首轮没有证明特殊选择算法优势。若只胜过单个随机组，不声称优于“随机策略总体”。
