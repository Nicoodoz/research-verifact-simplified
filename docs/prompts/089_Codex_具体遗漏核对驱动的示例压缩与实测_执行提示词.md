## 三、构造的实质修订

### 3.1 有限证据范围，不要求证明整个EHR缺失

构造器和核对器看到的是某一示例的完整原reference，不是完整患者EHR。所有“未涉及”“遗漏”的判断严格限定在这个可见来源。

区分三件事：
1. 原文可追溯：程序可以严格验证；
2. 具体事实及限定是否保留：可做有出处的模型辅助核对，但不是医生认证；
3. 是否保持或提高目标任务表现：只能靠冻结后的患者外比较回答。

NA并不意味着必须自动复制全文。需要检查整个可见源中与事件、属性、数值、主体、时间有关的信息，并保留其相关上下文；不能仅靠精确词匹配，也不能把“当前删减片段没写”推成“整个EHR不存在”。已知示例标签不允许用来选择性删掉支持或反向事实。

### 3.2 保留来源单元，不同时换所有变量

优先复用088已有passage单元、起止位置、日期/note metadata和原顺序。最终reference只能复制原文单元及原有metadata，不能生成新事实、解释或“缺失证书”。原单元自身的断句局限如实记录。

短reference≤1200字符或只有一个单元，继续原样保留。其余采用一个固定的约50%初始长度预算，不搜索25/50/75等多个比例。优先使用已有可信tokenizer；不可用时继续明确标注的长度代理，真实Judge token以回执为准，不能因tokenizer安装问题阻塞研究。

### 3.3 P：列清具体信息，再由程序组合，而非一票“保留全文”

给固定构造模型输入claim、完整源单元、原医生标签与预算。输出可包含：

- 每项与claim直接相关的信息及其原文短引文、源单元ID；
- 支持、反向/限制、相关但不足等作用；
- 需要一起出现的主体、日期、否定、可能性、事件状态或数值依赖；
- 明确重复的信息，及哪一个保留单元可作为同义代表；
- 推荐的候选IDs及普通相关性排序。

“需要时间线/背景”必须指出具体claim部分和具体源内容，不能把所有病程默认变成必选。重复判断必须考虑日期、事件和限定差异，不能把相似词面直接当成同一事实。

可以用简单的集合覆盖、枚举小规模组合或稳定贪心，选出满足已列出的关键内容与依赖的较短原文集合。选择只用源信息和长度，不用目标GT或任何下游分数；不把未经评价的组合当成性能最优。整段选择器不需要复杂新依赖。

第一阶段须产出明确候选及具体问题清单，不使用“preserve_full=true”作为无需举证的总开关。如果必须保留很多内容，列出造成该结果的具体约束；若这些约束确实覆盖全部源单元，明确说明。

这只是可审计的构造假设，不能把LLM生成的信息清单称为医学gold或数学保真证明。

### 3.4 Q独立产生，不能因为P回退而跳过

Q使用同一构造模型、相同源单元、claim、标签、格式和生成预算，按一般相关性、主题覆盖及去冗余产生真实候选与排序。不使用P的特殊覆盖约束，也不读取P选择了哪些单元。

**所有可压缩长槽都必须执行Q的独立构造，即使P保留原文。** 不允许再次出现“P保留全文，因此Q未经调用也记为全文”的捆绑。

P/Q最初使用相同预算。P后续若有具体补回而增长，可用Q自身已冻结的排序作一次确定性的长度匹配，但不能看目标结果或照抄P内容；Q的原始候选也要保存。不要为了严格等长把两臂一起回退原文。

匹配以一个完整单元或约5%的误差为参考，不padding、不剪断单元。若最终长度差较大，照实报告并限制P−Q的纯机制归因，不能虚称严格同token对照。

### 3.5 具体遗漏核对：完整保留风险信息，取消无出处否决

用已授权的阿里云模型完成一次独立请求的源对照检查，P/Q同规格、同次数。优先使用与构造器不同的现有DeepSeek作为核对器；发送前固定模型/参数，核对成本计入总预算。核对器不看医生label、臂名、构造器解释或目标病例。

输入：claim、完整原reference、候选reference、源单元映射。它必须针对被删除部分输出：

- 真正遗漏的相关信息对应的单元ID、原文引句；
- 与claim哪一部分相关；
- 已保留内容为什么没有覆盖该信息；
- 是缺失事实、限制、反向信息还是必要的跨段依赖。

纯重复、无关事实或“万一还有别处记录”“可能还需要背景”等泛泛疑虑，单列为未定位/非决定性提醒，不直接触发全文回退。核对器看得到完整有限源，不把未提供的整个EHR当作必须补齐的条件。

程序验证引文及ID，仅接受确实在被删部分的出处。对有出处且明确与claim关系相关的问题，最多一次追加所指源单元及依赖；不根据是否更接近医生标签决定保留哪个问题，也不删除现有反证。

不能机械认为“有ID的任何担忧都正确”。若问题与已保留文本重复、原文并未说该事实、或没有解释与claim的联系，记录处理依据；源核对的语义可靠性仍须在限制中承认。常规不确定性不是终止整个研究的理由。

存在不可修复的来源错误、明确关键内容丢失且只能全文恢复时，该臂该槽可以恢复原文；**不连带恢复另一臂**。不循环查询直至得到同意，不把核对器自身的分类一致性当成保真证书。

### 3.6 构造可复用性，而非只手工剪四例

在构造规则冻结后，可将同一函数用于086已冻结12条D候选池中其余示例，只统计源覆盖、压缩幅度、具体补回/回退和格式问题，不测下游选择效用、不据这些结果改prompt、不把它们替换进F4。优先复用原四例结果，不重复调用。

这项构造覆盖检查应在构造总预算2元以内进行；不足时保留四例主任务，不牺牲主评价预算。它能说明实现没有硬编码四例，不能证明跨示例分类效果。

## 四、冻结候选并进入真实评价

把原F4及本次P4/Q4的文本、hash、源diff、初始/补回IDs、核对问题和长度一次性冻结，再接入目标评价。

客观输入关系决定去重，不由模型的“预计有用”决定是否测：

除输入没有区别、真实来源问题或费用/服务异常外，候选必须进入已冻结的主评价。即使前几十条不理想，也不能择时停止、换文本或重挑样本。
