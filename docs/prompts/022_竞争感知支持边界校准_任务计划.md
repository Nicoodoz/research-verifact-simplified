## 三、主研究问题与候选方法

### 3.1 三个需要回答的问题

1. λ=2的救回与误伤，是否随NS/NA相对竞争强度呈现可利用的差异，而不只是整体类别比例或支持分数高低的结果？
2. 有针对性的条件偏置，能否优于固定λ=2，并且提供**超过重新拟合一个全局λ、普通多类偏置或标准校准**的额外价值？
3. 改进在患者外推的开发评价、重复调用以及可选跨模型测试中是否稳定？代价落在哪些类别和患者上？

### 3.2 先保持原方法定义不变

沿用019/020的三类标签及评分prompt。设模型输出整数分数为 `score_k`，保持其合法性校验：三类齐全、各在0–100、总和100。冻结变换为：[P5]

\[
z_k=\log\left(\max(\mathrm{score}_k/100,10^{-6})\right).
\]

U0选择最大 \(z_k\)；U2只给Supported项加2。平分仍按 **NS、NA、S** 的优先顺序处理。不能改零分处理或平分规则后仍称原U2。

这些是模型生成的相对信心分数，**不是模型token logits，也不是已验证的概率**。softmax规范化可用于比较概率质量，但不能因做了规范化就宣称完成校准。

### 3.3 推荐主候选：平滑的NS/NA竞争感知偏置

先计算两个非支持类别内部的相对权重：

\[
r_i=\frac{e^{z_{NS,i}}}{e^{z_{NS,i}}+e^{z_{NA,i}}}.
\]

然后把统一的λ改为：

\[
\lambda_i=r_i b_{NS}+(1-r_i)b_{NA},
\]

\[
\widetilde z_{S,i}=z_{S,i}+\lambda_i,\qquad
\widetilde z_{NS,i}=z_{NS,i},\qquad
\widetilde z_{NA,i}=z_{NA,i}.
\]

最终标签仍取调整后最大分数，并保持原平分规则；概率评价使用
\(q_i=\operatorname{softmax}(\widetilde z_i)\)。

该主候选只有两个全局待拟合参数。NS分数相对较大时，Supported偏置更接近 \(b_{NS}\)；NA相对较大时，更接近 \(b_{NA}\)。不是每个患者拟合两个参数，也不另加模型读取EHR。

它有三个需要保留的性质：

- 当 \(b_{NS}=b_{NA}=2\) 时，准确退化成现有U2；两者相等但可学习时，退化成学习全局λ。
- 使用平滑权重，避免NS/NA分数接近平分时，因“谁略高一点”而突然切换校准规则。
- 不直接改变NS与NA的相对顺序。因此它不能解决所有NS↔NA误判，能力边界必须明示。

“NS竞争较强时应更谨慎，即 \(b_{NS}<b_{NA}\)”仅是动机假设，**不是预先认定的事实，也不应通过强制参数顺序来制造结论**。高NS分数只是模型自身判断，不是独立的矛盾证据。

建议通过训练折上的三类NLL拟合参数，并对偏置大小及两参数差异作适度正则化；普通可学习基线采用相同拟合目标，避免不公平比较。默认不做类别重采样或按作者设置不同λ。拟合目标、正则化选择和权重方案须在正式比较前登记。实现细节交由Codex合理决定。

### 3.4 避免形式上的“升级”

不以增加参数个数代替实际能力增加。单一正温度缩放不改变argmax；若原方案只是 \(\sigma(a m+b_c)>0.5\)，且 \(a>0\)，分类边界只取决于 \(-b_c/a\)，三个参数不等于三个独立分类自由度。022不将它们包装为天然更强的分类方法。

本轮优先只研究上述主候选。没有清楚证据时，不继续叠加神经网络、动态证据特征、患者特征或多agent。它是**需要标签拟合的轻量后处理**，可以称“不微调基础LLM”，不能称“完全training-free”。

## 四、对照必须足以排除“只是多调了参数”

所有后处理方法尽量共享同一条评分请求的原始输出，不为每种校准器重新调用Judge。

| 对照/候选 | 目的 |
|---|---|
| U0 | 判断未调整评分的表现。 |
| **固定U2：λ=2** | 当前必须保留的强基线，不重新挑值。 |
| 学习一个全局λ | 排除“只是给阿里云或当前队列重新选了一个常数”。 |
| **竞争感知双偏置** | 022唯一优先主候选。 |
| 多类常数偏置 | 两个独立偏置自由度的普通对照，检验相同参数量下是否真需要条件结构。 |
| 正则化vector scaling | 标准、可改变类别边界的更灵活校准参照。不能只挑弱基线。 |

此外保留同期原structured **B**、评分请求直接返回的 **V_raw**，以及 **Always-S** 诊断；可加入temperature scaling，但它主要用于NLL/Brier等概率指标对照，不能期待仅靠正温度提高PA/MCC。B、V_raw没有完整类别概率时，不为它们编造概率来计算NLL。

温度缩放、向量缩放、多类偏置和概率后处理已有研究背景；LLM标签偏置也不是新的问题。[R1–R3] 本文主候选是待检验的应用研究方案，**尚未证明其公式具有文献首创性**。执行阶段应做有针对性的相关工作核对；不能将标准方法改名当创新。

## 五、数据使用与分阶段执行

### 阶段A：历史输出上的零API开发筛查

优先整理019和020已有的scoring输出及冻结C48。已知范围为6＋10名患者、650＋879＝**1529条不同claim**，但须先核对ID和重复关系，不能假设所有40名development都有同规格三类评分。[P2、P3、P6]

先做与本问题直接有关的诊断：U0→U2救回/误伤分布、NS→S与NA→S分别的变化、支持margin与NS/NA竞争权重的联合分布、不同患者和作者的差异。单看被救回样本不能证明存在可泛化结构，应同时看误伤与未改变样本。

在同一批历史输出上比较主候选及规定基线。这一阶段目的是发现实现问题、判断是否值得收费验证，**不是新方法的独立确认**。若条件结构没有稳定的患者外推信号，普通全局λ已经同样好，允许停止并形成负结果报告，不为凑先进方法继续扩展。

### 阶段B：阿里云主实验

阶段A有合理信号后，冻结主方案、拟合规则、队列、分折与评价，再获取阿里云输出。优先复用上述16名患者的冻结API-BGE reference；不强制补齐其余24名development患者，更不使用reserved test。

预算允许时，对选定队列运行B和scoring两种prompt，各独立重复两轮。所有校准器在每轮共享该轮scoring输出；U2无需额外调用。若预算或调用量不合适，可先缩减为预先固定的患者子集；也可将B的第二轮降为诊断优先级，但必须在查看对应结果前登记，不能根据哪轮好看来省略另一轮。

采样以**患者为单位**，优先保留选中患者全部valid atomic claims。不要只抽λ=2曾救回的样本、NS错误样本或高置信样本作为主队列。小预算下应优先保留患者数量与自然分布；病例富集只可作为另列的诊断分析。

阿里云结果与历史硅基流动结果分开保存、分开解释。新后端基线变化不能算作022方法收益；即使患者相同，也不能把旧B与新校准器作“同期公平比较”。

### 患者级拟合与评价纪律

本轮采用患者分组的交叉验证，报告**折外预测**：某位患者的预测只能由未使用该患者标签的校准器产生。患者数量允许时，建议固定4折外层；正则化等选择只在外层训练患者内部完成，采用嵌套分组验证或事前固定设置。[R4]

同患者的human/LLM文本、所有claim、R0/R1以及不同供应商或模型的输出必须保持在同一组。不能把R0放训练、同患者R1放测试，或把DeepSeek下的患者标签用于拟合后，再称同患者Qwen评价“未见患者”。

历史混合数据的主拟合可每条claim取预先指定的首个合法评分，避免020因有两轮而天然获得双倍权重；第二轮留作输出稳定性诊断。阿里云两轮也建议先在训练患者R0拟合，使用同一组折内参数评价留出患者的R0与R1。其他处理可合理调整，但要说明重复权重，不能把重复当新患者。

**交叉验证不能抹去既往开发暴露。** 022根据019/020结果提出，历史020对新方案已经不是独立确认集；新阿里云调用也不使这些患者重新变成未见患者。022仍定位为development研究，reserved40的最终评价留到以后单独授权、冻结后进行。

## 六、评价目标与继续/停止标准

### 6.1 评价内容

沿用002公共评价接口，主范围明确登记为与020衔接的 **all valid atomic claims、三分类micro PA/MCC**；AC1辅助，同时完整报告human/LLM分层，不能因总体较好而隐去LLM子组。该范围是022主动登记的选择，不由其他旧任务默认设置悄悄决定。

必须同时报告：

- 三类混淆矩阵、precision/recall，以及false-S数量和以真实非S为分母的比例；NS→S与NA→S分别列出。
- 相对U2的救回、误伤及“本来已经错、后来变成错误支持”的转移，防止只看净正确数掩盖代价。
- NLL、Brier和类条件可靠性诊断；ECE作为辅助，固定分箱并交代小类样本量，不以ECE一个数证明校准成功。
- 各患者的收益、拟合参数跨折变化、两轮标签翻转；不要只给总表。

分类提升和概率校准提升分别判断：PA/MCC变好不自动证明概率可靠，NLL变好也不自动证明分类更强。类比例差异可能影响最优偏置，不预设为纯粹的“模型支持偏保守”。

### 6.2 主比较与开发筛查判定

**首要比较是主候选相对固定U2，其次是相对学习全局λ及普通校准基线。** 原VeriFact O可以作为同ID历史系统参照，但不是判定本轮结构贡献的主要依据。

建议将以下作为结果前登记的开发筛查目标：主候选相对U2的MCC点估计提高，PA降低不超过1个百分点，false-S率不增加、NS召回不下降，并实际减少NS→S错误。若做两轮，方向应基本一致，不能依赖挑轮次或单个患者。这里的1个百分点是工程开发容忍度，**不是临床安全界限**；执行者可在正式结果产生前给出更合适的固定门槛及理由，但不得看结果后调整。

结果解释遵循：

- PA和MCC都提高，才称总体分类性能提高；PA略降而错误支持减少，应称权衡改善。
- 只胜过固定2，但不胜过学习全局λ，说明主要收益可能来自重新拟合常数，不能归功于竞争感知结构。
- 普通偏置/vector scaling同样好或更好，应承认标准方法足够，不强推主候选。
- 只有NLL/Brier改善而分类目标不达标，可以形成概率质量发现，但不称完成本轮分类升级。

对配对差值沿用1000次患者cluster bootstrap，给出区间而非只报点值。**区间跨0不证明等价或没有影响**；需要非劣/等价结论时，必须事先定义相应界限并按区间判断。基于已固定折外预测的bootstrap主要描述这批开发输出的不确定性，不涵盖全部方法选择和拟合不确定性，不冒充最终确认性检验。

## 七、Qwen扩展：有价值，但非强制

本轮默认先完成DeepSeek主线；只有主实验完整、剩余预算足够且问题明确时才调用阿里云 `qwen3.8-27b`。[M2]

优先回答“参数能否不重调迁移到另一个模型”，而不是简单加一张Qwen绝对成绩表：选取预先固定的多个development患者，获取Qwen scoring输出；比较Qwen自己的U0、固定U2，以及由**其他训练患者**DeepSeek输出拟合的校准器。同一次Qwen输出供各方法共用，不按方法数重复收费。

如果再做Qwen自身参数拟合，必须另列为“目标模型重新校准”，并在Qwen患者内继续训练/评价分离。它不能冒充零调参迁移；也不能把同患者另一模型的标签信息视为不泄漏。

跨模型转移失败可以揭示适用边界；不能因此在Qwen全体评价样本上重新调到好看后宣布通用。此扩展最多支持跨模型结果，**不支持跨医院或跨数据集泛化，也不证明27B在3060 6GB上本地部署可行**。
