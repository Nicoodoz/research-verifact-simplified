# 文献章节阅读
按章节建立检查清单。不同论文的章节名称可能不同，但通常可以映射到以下结构。

1. 标题、关键词和摘要

关注论文究竟研究什么，以及作者如何定位工作。摘要应帮助读者快速判断论文的相关性、新颖性和主要贡献，但不能替代正文中的证据。关注：
	- 标题是否准确反映研究对象、方法和任务？
	- 关键词是否覆盖核心概念？
	- 摘要是否包含完整链条：问题 → 现有局限 → 方法 → 方法之间的区别 → 主要结果？
	- 摘要中的方法目标是否与正文一致？
	- 摘要是否出现正文没有支持的新结论？
	- 摘要是否把“发布结果”“估计量”“重建结果”等概念混用？

2. Introduction

引言应回答“为什么研究、已有工作哪里不足、本文做什么”。重点检查：

	- 应用问题和现实意义是否明确？
	- 研究对象是什么，是样本、位置、向量、轨迹还是数据集？
	- 未保护或未解决该问题会带来什么后果？
	- 相关工作是否被概括，而不是简单罗列文献？
	- 研究空白是否明确、具体且有文献依据？
	- 研究目标是否直接回应研究空白？
	- 目标所需的 requirements 或 challenges 是否说明？
	- 方法概述是否足够让读者理解整体思路，但没有提前堆积技术细节？
	- 实验概述是否说明验证了哪些问题？
	- 贡献总结是否是真正的新贡献，而不是重复研究目标？
	- 还要检查引言中的术语是否与后文一致。例如，如果论文定义的是 released location，就不应在引言中随意称为 reconstructed location 或 location estimate。

3. Related Work

Related Work 的重点不是“引用了多少文章”，而是“是否形成了有逻辑的研究版图”。应关注：

	- 开头是否先说明分类标准？
	- 分类之间是否存在层级关系？
	- 同一类别的工作是否集中介绍？
	- 每类工作是否说明其共同特点、适用范围和主要局限？
	- Research gap 是否在该类别完整介绍之后提出？
	- 不同类别之间是否有自然过渡？
	- 引用是否真正支持对应的观点？
	- 是否把不同模型、数据域或任务混在一起比较？
读完后，应能回答：
现有方法有哪些主要路线？每条路线解决了什么问题？它们共同留下了什么空白？

4. Background 或 Preliminaries

这一章用于建立后文所需的概念和数学工具。检查：
	- 定义是否足够支持后文理解？
	- 符号、变量、域和参数是否清楚？
	- 定理或性质的条件是否完整？
	- 背景知识是否真的被后文使用？
	- 是否把标准知识写得过多，却没有解释其与本文问题的关系？
	- 关键概念是否在后文被改变含义？

5. Problem Formulation

这一章决定论文研究问题是否真正被形式化。应重点寻找：
	- 输入对象是什么？
	- 输出对象是什么？
	- 输入和输出属于什么域？
	- 表达研究问题的完整映射是什么？
	- 目标函数或设计目标是什么？
	- 约束条件是什么？
	- 变量是否在使用前或使用后定义？
	- 是否引入了不必要的重复符号？
	- 还要判断公式是否真正表达“研究问题”，而不是仅仅罗列符号。

6. Method Overview

方法章节的第一段应让读者知道系统由哪些部分组成。阅读时关注：
	- 方法有几个阶段或模块？
	- 每个阶段或模块的输入和输出是什么？
	- 阶段或模块之间如何连接？
	- 架构图是否与文字描述一致？

如果存在流程图，应检查：
- 图中的变量是否与正文一致；
- 图中的箭头是否表示真实的数据流；
- 图中是否暗示了论文没有定义的“处理过程”。

7. Method Details
每个机制、模块或子步骤都应按以下顺序理解：目标 → 原理与直觉 → 设计 → 公式或推导 → 讨论 → 小结，具体检查：

- 目标
	- 这一部分要解决什么问题？
	- 它优化的是准确率、偏差、方差、紧凑性、信息量还是计算效率？

- 原理与直觉
	- 为什么采用这种网络结构、概率分布或网络模块？
	- 设计选择如何由目标和约束推出？
	- 是否直接给结论，却没有解释原因？
- 设计
	- 参数如何定义？
	- 参数是理论推导、优化得到，还是经验设定？
	
- 公式或推导
	- 每个公式中的项来自哪里？
	- 归一化常数、体积、积分和概率是否有解释？
	- 公式是精确等式、上界、近似还是经验表达？
	- 定义、假设和推论是否区分清楚？

- 讨论
	- 该设计的优点和代价是什么？
	- 是否存在偏差、收缩、噪声放大、边界效应或计算开销？
	- 该方法在哪些条件下可能失效？
	- 这一性质对后续模块或实验有什么作用？

8. Theoretical Analysis

理论部分不应只看证明是否形式正确，还要看定理的作用。重点关注：
	- 定理的假设是否明确？
	- 假设是否正是机制定义时使用的条件？
	- 定理是独立获得的结论，还是由定义直接保证？
	- 证明是否包含关键技术步骤，而不是重复定义？
	- 定理结论是否在后文被实际使用？
	- 理论结果是否解释了方法的设计或实验现象？
	- 是否夸大了理论保证的范围？

9. Experimental Setup

实验设置应独立于结果解释。检查：
	- 数据集来源、规模、维度和预处理是否明确？
	- 数据集为何适合验证研究问题？
	- 对比方法是否具有代表性？
	- 对比是否公平，例如对比指标、输入域和输出域是否可比？
	- 指标分别衡量什么物理意义？
	- 参数范围、默认参数和重复次数是否说明？
	- 消融实验是否只改变一个组件？
	- 敏感性实验是否只改变目标变量？
	- 运行时间是否说明硬件、实现和计时范围？
	- 实验设置中不应提前解释主要结果，也不应把结果表格中的结论重复写成设置说明。

10. Results 或 Overall Utility Comparison

结果阅读顺序应是：实验结果主要趋势 → 重要比较 → 机制或数据解释。应关注：
	- 结果是否直接回答研究目标？
	- 随参数变化，方法排名如何变化？
	- 两种方法是否在不同参数下呈现互补优势？
	- 是否存在数据集或参数例外？
	- 例外是否被明确指出？
	- 解释是否来自机制特性或数据特征？
	- 是否把相关性错误地表述为因果关系？
	- 不同指标是否有不同排名，原因是什么？
	- 文字是否只是重复表格数字？

对于图表，应同时检查：
	- 图例、坐标轴和单位是否清楚；
	- 图中方法名称是否与正文一致；
	- 图号和引用顺序是否正确；
	- 文字描述是否真的符合图中趋势；
	- 是否只强调有利结果而忽略明显例外。

11. Ablation Study

消融实验要回答“每个组件是否有增量贡献”。阅读时关注：
	- 完整方法由哪些组件组成？
	- 每个变体去掉或替换了哪个组件？
	- 比较顺序是否能隔离单个组件的作用？
	- 是否使用相同数据、相同随机条件和相同参数？
	- 组件带来的改进是否在多个数据集和参数下稳定？
	- 是否同时讨论效用提升和计算代价？
	- 结果是否支持作者对组件作用的解释？
	- 不能仅凭“完整方法最好”就断言每个组件都有效，需要看增量比较。

12. Sensitivity Analysis

敏感性分析应回答“参数变化带来什么效用—成本权衡”。检查：
	- 改变的是哪个参数？
	- 参数为什么需要分析？
	- 效用随参数变化的趋势是什么？
	- 计算成本如何变化？
	- 是否存在收益饱和点？
	- 默认值是否由实验结果支持？
	- 默认值是全局最优，还是实用折中？
	- 如果作者选择一个默认参数，应说明它是基于效用和成本的平衡，而不是未经解释的经验值。

13. Runtime 或 Computational Analysis

运行时间部分应先说明实验条件，再解释结果。应关注：
	- 硬件、软件和实现是否一致？
	- 计时是否包括数据加载、预处理、缓存和后处理？
	- 不同方法是否属于不同计算 regime？
	- 实测时间是否被误写成硬件无关的复杂度结论？
	- 理论复杂度与实际运行时间是否一致？

需要区分：
	- 渐近复杂度；
	- 特定实现下的实测运行时间；
	- 特定硬件配置下的性能。

14. Discussion 或 Limitations

如果论文有 Discussion，应重点判断作者是否正确解释了结果。关注：
	- 结果意味着什么？
	- 与已有工作的关系是什么？
	- 哪些结论具有普遍性？
	- 哪些结果可能只适用于当前数据集或实验设置？
	- 方法的边界条件是什么？
	- 是否讨论了失败案例、代价和开销—效用权衡？
	- 未来工作是否真正来自当前局限？
	- 好的 Discussion 不应重复 Results，而应回答“为什么重要、适用于哪里、不能说明什么”。

15. Conclusion
结论应简洁地回收全文主线。检查：
	- 是否总结主要贡献？
	- 是否概括两种方法的不同目标？
	- 是否说明实际应用范围？
	- 是否提出与当前局限直接相关的未来工作？
	- 是否引入正文没有出现的新方法、指标或结论？
	- 是否出现超过实验支持范围的普适性表述？
	- 是否错误使用术语？
	- 是否与摘要和引言中的贡献保持一致？
	- 结论应是全文论证的压缩版，而不是新的结果段落。

16. Appendix、Supplementary Material 和 References

附录和补充材料不能忽略，应检查：
	- 关键证明是否完整？
	- 算法伪代码是否与正文公式一致？
	- 额外实验是否支持正文结论？
	- 超参数、实现细节和数据处理是否放在补充材料中？
	- 引用的原始论文是否真正被阅读和准确概括？
	- 参考文献是否存在重复、缺失或引用对象不匹配？

17. 跨章节一致性检查

读完每章后，还要做一次横向核对：
	- 摘要、引言和结论是否表达同一组贡献？
	- Problem Formulation 中的符号是否贯穿 Methods 和 Experiments？
	- 方法输入、私有报告、后处理输出和最终发布对象是否始终区分？
	- 理论保证是否与实验设置一致？
	- 指标定义是否与结果描述一致？
	- 图、表、公式和章节引用是否按顺序？
	- 方法名称、缩写、数据集名称和参数是否统一？
	- 结论是否超出理论和实验支持范围？

# 文献章节阅读

- 略读：第一遍先读标题、摘要、图表和结论，快速判断论文的问题、方法、结果和价值。

- 简读：第二遍阅读引言和相关工作，重点识别论文的创新性和贡献。

- 详读：第三遍阅读 Experimental Setup、Results、Ablation、Sensitivity、Runtime 和 Appendix，重点验证实验是否真正支持方法优势，以及结论是否可复现。

- 全读：第四遍阅读 Problem Formulation、Method 和 Theoretical Analysis，重点核对研究空白、方法逻辑、公式来源和理论边界。

- 形成阅读证据链：研究问题是什么 → 为什么重要 → 现有方法缺什么 → 本文如何形式化 → 方法为何这样设计 → 理论保证什么 → 实验如何验证 → 结果说明什么 → 结论边界在哪里。

- 阅读一篇科研论文时，核心不是逐句翻译，而是依次回答五个问题：
1. 这篇论文与我有关吗？
2. 它的新意是什么？
3. 它的结论可信吗？
4. 方法和结果能否复用？
5. 它的结论边界在哪里？

# 阅读笔记

1. 应用问题与研究意义

首先关注：
- 论文解决的现实问题是什么？
- 研究对象、数据对象或任务对象是什么？
- 该问题为什么重要？
- 未解决该问题会造成什么影响？
- 论文讨论的是单个样本、单个位置、整条轨迹，还是更高层级的数据对象？
需要特别注意论文的研究范围，避免把局部值或群体统计混为一谈。

2. 相关工作与研究空白

阅读 Related Work 时，应先判断作者采用了什么分类标准：
- 按任务或应用分类？
- 按环境条件分类？
- 按技术内核分类？
- 按集中式与分布式处理分类？

然后检查：
- 同一类别中的相关工作是否完整介绍？
- 作者是否准确概括了已有方法的目标、优点和局限？
- Research gap 是否在完整介绍该类别后提出？
- 不同类别之间是否存在清晰的层级和过渡？
- 所谓“现有方法不足”是否确实由文献支持，而不是为了突出新方法而夸大？
核心问题是：作者提出的新方法究竟填补了什么具体空白，而不是仅仅“提出了一个新模型”。

3. 研究目标、要求与挑战

需要区分三个层次：
- Objective：论文最终想实现什么；
- Requirements：为实现目标必须满足什么条件；
- Challenges：为什么这些条件难以同时满足。

阅读时应检查：
- 研究目标是否明确、可验证？
- 目标是否与前文研究空白对应？
- 约束条件是否形式化？
- 是否存在多个相互冲突的目标，例如开销与效用、紧凑性与无偏性？
- 作者提出的方法是否真正针对这些要求或挑战，而不是解决了另一个问题？

4. 问题形式化

Problem Formulation 是判断论文是否严谨的关键部分。应重点寻找：
- 输入是什么？
- 输出是什么？
- 输入和输出分别属于什么域？
- 完整映射或函数是什么？
- 随机性出现在哪里？
- 一个研究单元是什么？
- 目标函数、约束条件和评价对象分别是什么？
- 若涉及序列或轨迹，单点映射与整体映射是什么关系？
尤其要检查符号是否统一。一个重要问题是：论文输出究竟是 released output、post-processed output，还是 estimator。如果论文定义的是最终发布对象，就不应随意称为 reconstruction 或 estimate。

5. 方法或模型设计

对于每个机制、模块或步骤，应按照以下顺序理解：
	- Goal：目标是什么？
	- Principle and intuition：为什么采用这一原理？
	- Design：具体如何设计？
	- Formula or derivation：公式如何由目标和设计推出？
	- Discussion：有哪些权衡、假设和适用条件？
	- Conclusion：该步骤最终保证了什么？

阅读时重点检查：

	- 每个设计选择是否有动机？
	- 几何结构、参数、损失函数或网络模块是否是由目标推导出来的？
	- 公式是定义、推导结果，还是经验设定？
	- 定理是独立证明的结论，还是定义过程中直接使用的条件？
	- 不同模块的输入输出是否清楚？
	- 关键概念是否被正确区分？
	- 架构图是否与文字和公式一致？


6. 相关公式与理论结论
不要只看公式是否“形式正确”，还要追问：
	- 公式中的每一项来自哪里？
	- 是否解释了体积、积分、归一化常数或概率的来源？
	- 公式是否依赖某个未说明的假设？
	- 定理结论是否与定义保持一致？
	- 公式表达的是精确结果、上界、近似，还是经验拟合？
	- 闭式解是否一定存在？是否唯一？如何求解？
	- 理论性质是否真正影响后续设计或实验？

7. 实验设置

先单独阅读 Experimental Setup，不要将设置和结果混在一起。应检查：
	- 使用了哪些数据集？数据集分别代表什么场景？
	- 数据规模、维度、预处理和归一化方式是什么？
	- 对比方法是否具有代表性？
	- 对比方法的输入域和输出域是否公平？
	- 评价指标分别衡量什么物理意义？
	- 参数、重复次数和随机种子是否说明？
	- 消融实验是否真正只改变一个组件？
	- 敏感性分析改变了哪个变量？
	- 运行时间是否在相同硬件和实现条件下比较？

8. 实验结果与证据

结果部分可以按照以下顺序阅读：
	- 结果图或表的主要趋势；
	- 关键方法比较；
	- 机制或数据特征解释。

应关注：
	- 结果是否直接回应研究目标？
	- 作者是否只报告重要现象，而不是机械重复表格数字？
	- 结果解释是否有机制依据或数据依据？
	- 作者是否把相关性错误地写成因果关系？
	- 是否存在数据集或参数条件下的例外？
	- 不同指标是否可能给出不同排名？
	- 消融结果能否证明各组件的增量作用？
	- 敏感性结果是否支持默认参数选择？
	- 运行时间结果是否按计算机制或复杂度 regime 解释？



9.术语与符号一致性检查

建立一个简单的 terminology and notation ledger，逐项核对：
	- 方法名称和缩写是否一致？
	- 同一个变量是否被重复命名？
	- 私有报告、后处理结果和最终发布结果是否区分？
	- 指标名称、单位和符号是否统一？
	- privacy guarantee 的粒度是否一致？
	- 图、表、公式和章节编号是否按顺序引用？
	- 结论中的术语是否超出了正文定义？
这是发现论文深层问题的重要方法。很多论文的问题不是单句语法错误，而是同一个对象在不同章节被赋予了不同身份。

10. 可复现性与适用边界
最后应判断：
	- 其他研究者能否根据论文复现方法？
	- 关键参数、算法步骤和数据处理是否足够明确？
	- 是否依赖未公开的候选域、外部元数据或原始数据？
	- 方法适用于哪些维度、数据域和任务？
	- 实验是否支持作者声称的普适性？
	- 哪些结论只是当前数据集或当前实现下的观察？
	- 未来工作是否真正来自当前局限，而不是泛泛而谈？

11. 一句话总结
阅读科研论文时，最重要的是建立一条完整证据链：
应用问题 → 研究空白 → 形式化目标 → 方法设计 → 理论保证 → 实验设置 → 结果证据 → 适用边界。

如果其中任意一环缺失，例如目标没有形式化、设计没有动机、公式没有来源、实验没有对应指标，或者结论超出了实验支持范围，就说明论文的论证仍不完整。
