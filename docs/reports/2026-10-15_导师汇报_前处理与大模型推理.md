# 导师汇报：前处理与大模型推理

截至097。**全部为raw标签，不含后处理。各表内同ID比较，跨表不作差；均为已有研究暴露的开发材料。** PA＝正确率；错误支持＝真实非S却预测S。

## 一、与原VeriFact的差异

|模块|原VeriFact较强发布配置|本项目|
|---|---|---|
|前处理|100条句子事实；BGE-M3稠密＋学习稀疏检索、融合、重排|段落证据；稠密＋BM25，C48候选，再选最多16段、约8000字符|
|Judge|R1-70B；reasoning分支输出标签与简洁理由|V4 T-S：thinking-high，输出标签、理由、checks及三分数|
|教学示例|reasoning分支无示例；非reasoning有合成示例|F4：固定4个其他患者的医生标注示例，2S/1NS/1NA|

N-S＝非thinking评分；T-S＝thinking-high评分。C48是候选数，不是模型实际读取段数。[源码依据](../reading/01_原论文源码与路线审读.md)

### 1.1 前处理流程

|系统|从claim到Judge实际输入|
|---|---|
|原VeriFact较强发布配置|atomic claim → 同患者、目标住院范围的句子事实 → BGE-M3稠密＋学习稀疏召回与融合 → 去重、BGE重排、top100 → 按时间组织reference|
|本项目C48|原claim → 同患者、住院日期内的原文段落切片 → 稠密与BM25分别排序 → 交替保留48个不重复候选 → BGE重排 → 按约束选最多16段、约8000字符 → 按时间组织reference|

### 1.2 前处理具体差异

|环节|原VeriFact发布配置／作者代码|本项目实际实现|差异性质|
|---|---|---|---|
|核验目标与query|以atomic claim作为检索query|使用同一原claim，不改写目标、不加入目标出院总结上下文|共同设置，非新增方法|
|患者与时间范围|本对照为current admission；按患者和住院起止日过滤|按同患者、CHARTDATE落在入院至出院日期内筛选，排除出院总结|患者／日期过滤非新意；本项目实际用日期过滤，不是逐条HADM_ID硬匹配|
|源证据单位|本对照为sentence facts；原论文另比较过atomic源事实|直接从原始note取段落切片，不用LLM重写片段|句子级改为段落切片级；可能保留相邻描述，也可能增加无关文字|
|长文本切分|上述发布配置以句子为源事实单位|先按空行分段；超过640字符时，在后半段空白处继续切分，保存原文起止位置|不是语义事件切分，不保证限定词、列表标题或跨段关系完整|
|稠密召回|BGE-M3 dense|同模型家族的dense表示，按原claim计算相关性|模型家族相近；不能仅凭模型名认定输入／API数值等价|
|另一条召回路线|BGE-M3 learned sparse：模型生成token权重|本地BM25：词面匹配、词频和逆文档频率|BM25不是原作者的学习稀疏表示|
|候选合并|作者维护代码默认distribution-based score fusion，由向量库融合两路结果|各路先取前80；dense、BM25交替加入未重复ID，满48停止；候选足够时保留各路前24|C48用名额保留，非原作者融合，也非本项目A48的RRF|
|相关性重排|配置启用BGE rerank，之后限制topN；本对照最终100条|用原claim对48候选的检索文本做BGE rerank；检索文本含日期、类别、描述和正文|两边都有重排；重排分数是相关性，不是临床支持概率|
|同一note的容量|所核对topN链路没有本项目“每note最多2段”规则|按重排分数降序贪心选段，每note最多2段，总计最多16段|控制来源集中，也可能排除同note的关键第三段|
|去重口径|按TEXT精确重复去重|选段时仅对“日期＋类别＋正文”相同的片段去重|本项目允许跨日期重复正文保留；不等于识别重复临床事件|
|最终长度控制|按top100句子事实控制条数，不套本项目8000字符打包规则|逐段信息头和正文计入8000字符预算；放不下则跳过，不对已选切片再次裁尾；全局住院头另计|实际reference可略超8000字符；两系统并非等信息量比较|
|展示顺序|absolute_time：按时间排列，附入出院时间、日期、类别及描述|选段按相关性，入模前再按日期、时间、note和原文位置排列|时序展示并非本项目首创|
|输入中的来源定位|所核对absolute_time文本显示日期、时间、类别和DESCRIPTION；内部另有节点元数据|展示日期、时间、类别、Note ID和原文字符区间，并保存SHA；基础formatter不展示DESCRIPTION，但检索文本保留它|定位更细；DESCRIPTION没有直接给Judge，可能丢失检查名称等线索。不能说原系统没有内部溯源|

原系统列以发布`rater-121`实参为主；融合及格式细节依据归档作者代码`f115d36`，不反推论文每次运行均完全相同。[发布配置核查](../../outputs/010_verifact_baseline_alignment/report.md) · [作者检索与格式代码](../sources/007_context_retrieval/packages/llm_judge/src/llm_judge/reference_context.py) · [融合核查](../../tasks/009_retrieval_baselines/research_notes.md) · [本项目检索代码](../../tasks/009_retrieval_baselines/retrieval_baseline.py) · [切分与打包代码](../../tasks/008_retrieval_planning/planning_core.py)

## 七、汇报结论

|模块|已支持的结论|尚未支持|
|---|---|---|
|C48|输入和费用降低|稳定精度优势|
|T-S|部分队列降低错误支持、改善MCC|稳定准确率提升|
|F4|对本项目基线常有小增量；小队列可优于原作者|大范围准确率领先|
|组合|可改善本项目基线|整体稳定超过原VeriFact；组件效应可直接相加|

完整类别指标、混淆矩阵、患者区间及来源SHA见[复核台账](导师汇报_F4_raw复核.json)和[任务索引](../TASK_INDEX.md)。
