## 运行前固定的验证方案

- 开发患者按 003 原 seed+ID 哈希顺序，跳过 004/005 已用六名后取 45115、89909，不看旧模型表现选人。其 224 条 valid claims 作为候选池；本轮取每患者/作者 16 条，共 64 条。
- 在每个患者/作者层，先按固定 ID 哈希取最多 5 条 NS、5 条 NA，再取 S 补足 16；若某类不足则按同一哈希补齐。该预算约束、少数类加密抽样仅用于诊断，不代表自然类别分布或完整患者队列表现。保存所有入选和未入选 ID。LLM 候选没有 NA，不能声称验证了其 NA 召回。
- 统一上下文为完整 parent_text_chunk，加其在原 BHC 中紧邻前方最多 240 个原始字符；只接受 parent 唯一逐字定位，保留字符偏移和左边界截断标记。不得根据答案人工替换段落或补剂量、时间。总上下文不超过 1,200 字符；定位不唯一则报错、先检查，不静默选择一次出现或换样本。
- 三臂：ordinary structured；相同 structured 加未核验来源上下文；相同 structured 加重复 claim 的长度近似对照。都使用同一 claim、完整 R1/rater-121 reference、服务别名 DeepSeek-V4-Flash、temperature=0、thinking=false、max_tokens=2048、单次非流式 JSON 输出、相同五项解释结构和 200 英文词提示预算。每条命题的臂顺序按固定排列平衡。
- 重复对照按整句重复至最接近来源上下文字符数；不伪称实际 tokenizer 计数完全相等，也不认为重复文本是无作用的安慰剂。记录实际输入/输出 token、长度与延迟。三臂共同收到上下文角色限制：来源文本不能作为 EHR 证据，不能增补未断言条件或修正显式日期/数值；无法安全定位指代时保留不确定性。
- 主比较为 source_context − structured，repeat_claim 是必要诊断对照。调用 002 evaluate/paired_compare，原 GT 三分类 micro PA/AC1/MCC、1,000 次患者 bootstrap、作者分开。两患者区间只作描述，不能证明稳定优势；分数首先表示与原独立命题标签一致。
- 输入级分析单列可能新增日期、数值、剂量、否定/确定性及事件限定的情况；这些标记不是新的 GT，也不据此事后删除不利样本。对变化病例和固定对照核对完整输出/证据，分别记录目标保持、指代改变、附加限制、来源自证、错误事件引用和未解决情况。没有医生新增语境标签，不把人工解释当成上下文化临床正确率。
- 仅完整的作者/臂/配对评分；缺失、非法标签、截断保持失败，不补标签、不做 available-case，也不为了答案追加生成。三臂有合法标签但格式偏离时保留原标签、单列诊断。全部收费尝试受同一预算及每请求最多 5 次尝试限制，余额耗尽自动换号；未知结果暂停。
