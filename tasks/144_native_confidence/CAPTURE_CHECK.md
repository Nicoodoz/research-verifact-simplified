# 144：同次生成读取分数的小型工程验证

完整1817已经证明分数具有回顾性的风险排序价值。本段只回答后续部署能否在生成原标签时读取同一分支分数，减少额外prefill；不重训、不重新评价分类收益、不拟合阈值、不改变完整1817结果。

固定12个输入配置，来自原160中120/136各自原预测S、NS、NA的最短及最长各一例，共8个唯一ID；选择不用GT。每个输入只生成一次control和一次capture，共24次，按配对序号交替先后，成功首答全部保留，不因差异重发。完整reference与原prompt保留，BF16、batch1、greedy无thinking、384输出上限、16384容量一致。

两臂都开启`return_dict_in_generate`和`output_logits`审计，只有capture臂加入只观察、不修改scores的既有helper。仅在模型实际生成的前4个token等于冻结JSON前缀时记录；不强制前缀，否则记缺失。只保存两分支值、原内容/生成token指纹和必要结果，不保存整词表数组。

判读包括本次配对的输出、token、标签一致性，前缀覆盖，实际分支值及耗时。与旧batch2缓存比较只作辅助；主对照是同次配置下的control/capture。processor之后观察到的值不自动称为raw logits；`output_logits`可能有原地操作别名，二者数值相同也不能证明所有生成配置下等价。

固定600秒计算（包括加载、编码、编译和生成），另180秒保存，同一09:36:01起算20元窗口持续累计。先确认GPU空闲，保留全量结果与失败；不假设零开销，不将小样本一致性当作全队列性能保证。若接口不支持或出现差异，保留并报告，不自动改标签或扩大测试。此段没有原生分类提升或临床安全结论。
