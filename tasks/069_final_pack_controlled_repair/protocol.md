# 069：final pack 受控修复验证（收费执行前冻结）

## 研究目标与边界

在固定 053 T-S thinking-high scoring Judge 与 Frozen PriorG 下，判断 C48 内的证据包操作能否**稳定**修复原先错误，同时保护原先正确病例。066 的 GT-aware oracle 只用于第一步机制诊断，不是方法成绩；第二步选择器绝不读取 GT、oracle 选择或历史干预结果。全任务收费 API（预检、重复、重试、未知预留）累计≤人民币 8 元，所有阶段共用账本；不扩大检索、不换 Judge、不调 PriorG、不使用 reserved 开发、不按 HTTP200 答案择优重跑。不自动追加版本。

067 在 v1/v2 实现与正式来源上存在冲突，069 只作离线核查并提供单独更正说明，不改历史文件；不把 v1 的替换结果称为保守增补成绩。

## 第一步：固定 066 的 10 条 C48 内修复病例

样本恰为 066 `evidence_cases.csv` 中 `evidence_fix=True` 且 `kept_all_in_c48=True` 的全部 10 条，不按 069 响应再取子集。这 10 条覆盖 8 名患者、GT=S 7 条、NA 3 条，原 T-S+PriorG 均错。066 oracle 选择了真实原始 EHR passage，最终 Judge 请求不含 GT。对每条从同一已冻结 corpus 映射原 baseline reference 的 passage 和 066 实际送入 Judge 的 `kept_pids`；任何无法完整映射的病例不补造 ID，应停止相关对照并报告。

五个条件（所有正文均为真实原始 EHR）：

1. **B 原包重复**：精确复用 053 原 T-S 请求体，再调用一次；053 已有回答为 B0。
2. **O oracle 重复**：精确复用 066 final Judge 请求体，再调用一次；066 已有回答为 O0。O0/O1 仅用于上限的可重复性。
3. **A 只增**：原 baseline reference 逐字保留为前缀，只追加 `O\B` 的 C48 passage。已有段落不删、不重排。允许超过 8,000 字符以保留纯加法对照；报告长度，不能当作可部署预算匹配成绩。若 `O\B` 为空，不调用并机械等于 B。
4. **D 只删**：保留原 baseline reference 的 header、原文 passage 和原相对顺序，只留下 `B∩O`；若交集为空，此条件不可构造，不调用、不虚构空证据预测。
5. **C 组合**：原 baseline header 加上 066 实际 oracle reference，其 passage 组成与 O 相同；C/O 的唯一计划差异是 header，用来检查这一具体呈现因素。对两例历史原包片段与冻结 corpus 的字符存在差异，逐例披露，不能将所有差异强行归为加删的因果效应。

五条件中的 B/O 历史回答不重新计费。正式冻结新的 B1/O1/A1/D1/C1 请求体、指纹、样本 ID、费用上界后发送。HTTP200 内容无效不补标签或重跑；非200/未知按上界占用并停止新增发送。

### 预设重复与停止

第一轮后，仅对 A/D/C 中 **PriorG 后答对 GT** 的条件各发一次完全相同的重复（A2/D2/C2），且只在累计已付/未知预留+新请求保守上界≤8元时发送。此重复规则在观察第一轮结果前冻结；不改 prompt、模型、段落集合或阈值。B0/B1 同错且某一操作的首轮/重复均正确，才记为该操作的稳定修复。O0/O1 同对单列，不能代替 A/D/C 的稳定性。所有变化同时报告 raw Judge 与 PriorG 后标签；最终系统判断只按后者。

只有**同一操作**稳定修复≥3条、覆盖≥3名患者，且核心对照及所需重复完整，才进入第二步。若多种操作同时满足，按只增→只删→组合的固定简洁性顺序选择一种，不事后搜索条件组合。未满足、预算不足以完成关键重复或数据对照无效，停止第二步，结论为现有材料不足以支持 GT 盲开发；不通过改门槛继续。

## 第二步：条件触发的 GT 盲复现

候选队列在第一步新答案出现前确定：从 052 T-S 有效病例中，排除第一步 8 名患者与重复 proposition ID，按 SHA-256(ID) 顺序取原 baseline 错误 8 条、原 baseline 正确 12 条；这些标签仅用于评价分层，**不进入 selector 输入或 Judge body**。跨批次、患者隔离但仍属已开发 development，不是独立测试集。若某分层不足，按可用数量缩减且事前记录。

仅第一步过门槛时，冻结**一个**最小 GT 盲选择方案及其无变化规则。方案只能用 claim、原 final pack、同患者冻结 C48；不能看 GT、066 oracle passage、066/069 历史干预效果或病例名单的错误/正确分层。只对真正改变 reference 的病例调用同一 T-S Judge，未改变者复用原 052 回答。保护病例一并进入完整同 ID 评价。不得搜索多个 prompt、模型、分类器或后处理。

第二步报告全部 20 条的 raw 与 PriorG 后的 PA/AC1/MCC、false-S、逐例 rescue/harm、患者分布和固定重复。要称为值得继续的开发信号，至少须有 PriorG 后稳定 rescue≥2 条且跨≥2患者、保护病例 0 harm、false-S 不增加、净正确>0；否则停止当前版本。无论结果如何，不自动扩大到 reserved 或启动 070。

## 评价与交付

统一使用 `verifact_research.evaluation.evaluate` / `paired_compare`，默认 valid-only、三分类 micro、完整同 ID 和 1,000 次患者 cluster bootstrap。第一步是以 GT-aware oracle 挑出的错误病例组成的诊断样本，不计算部署方法的自然队列成绩；第二步单列原错误/正确分层，并说明人为加密带来的外推限制。保存协议、冻结请求、预算与回执、逐例结果、自检和中文报告。结论分别回答操作机制、重复性与 GT 盲可识别性。
