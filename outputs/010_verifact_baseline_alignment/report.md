## 实际比较了什么

复用009确认的6名开发患者、全部650条 valid atomic claims：LLM-written 243（S/NS/NA=228/10/5），human-written 407（313/27/67）。患者为原开发哈希顺序第19–24名：59250、93640、15057、27036、59840、66218。没有新患者；前24名开发已使用、剩余16名及40名 reserved test 的边界不变。这是已使用开发队列上的校准，不是新患者独立确认。

第一层从 release 的 verdicts、rater configuration 和 reference payload 逐条连接。唯一目标为 **v1.1.0-rater-121**：R1-70B、100 sentence facts、rerank、absolute_time、current admission、deduplicate=True。650条发布预测与002导出一致；每条 reference ID 与其文本 SHA-256 一致。sentence 指检索事实类型，最终评价对象仍为 atomic claim。原 Judge 为量化 R1-Distill-Llama-70B，另有 Llama-3.1-8B 结构化输出步骤，不能与本项目 V4-Flash 等同。

第二层原样使用两套**实际完整 reference**，两臂同期重新生成：009相同 `deepseek-ai/DeepSeek-V4-Flash`、common＋structured 提示、temperature=0、thinking=false、max_tokens=2048。原 claim 不变，来源句/BHC 和医生标签不进入 Judge；没有新检索、embedding、rerank、planner 或人工补证。C48 完整请求 body 与009一致。两臂按预设哈希交错、4并发执行。1300个主请求 body 均不同；另预先按每患者/作者选1条、两臂各重复，共24次，重复不替换主答案。

**未截短发布 reference 来匹配 C48。** 本任务校准两套已有最终证据包，内容、数量、metadata、结构和长度共同不同，不能将差值解释为纯检索或纯包装的因果效应。统一调用002评价：valid-only、三分类 micro PA/AC1/MCC、1000次患者 cluster bootstrap、作者分开、完整配对；两臂均650/650有效。

## 下一步判断及论文表述

1. **C48足够作为下一阶段实用对照，但须明确它是本地替代baseline。** 010没有证据表明其最终证据包整体落后于发布包；成本较低、note与原位置可追溯。原VeriFact的dense＋learned sparse/Qdrant流程与本地BM25＋dense不同，010没有完整复刻原索引和排序，也不伪造发布候选轨迹。
2. **继续有限的证据组织验证，先设清楚工程对照。** 优先检查“同一检查的身份＋结果、条件句＋状态、note时间＋事件时间”能否完整保留。最基本的metadata保留和避免切断条件，应作为工程修正/简单对照，不能包装成论文创新。是否有超出这些修正的研究收益，需固定候选、Judge及可比预算后单独验证；本轮没有实施新方法。
3. **不先大规模重做baseline，也不扩大planner或融合搜索。** 证据增加和丢失双向存在，Judge对时间、持续范围、计划/实施及NS/NA仍会出错。下一实验应同时检查证据是否完整和原GT一致性，保留无关背景对照与预设重复，避免只挑N180/N642式成功故事。先用已使用开发患者开发，冻结方案再考虑剩余开发；reserved test继续隔离。

可用于论文的已得到结果是：**在既有六患者队列上，将发布系统参考与同Judge证据包比较分开后，发布系统较高PA不能被简单解释为其reference在当前Judge下更优；证据身份/条件完整性与判断边界是并存问题。** 这属于baseline校准与探索诊断，不是新packaging方法有效性结论，不证明planner方向整体无效，也不构成临床金标准修订。[设置及定位草稿](paper_materials.md)与[核心结果表](tables_001/core_results.csv)可供后续写作。
