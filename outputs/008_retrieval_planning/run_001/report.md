# 008：LLM 检索规划有额外价值吗？

**能生成有针对性的短查询，也能补充有用记录；但本轮没有证明稳定的最终收益，不建议原样扩大或确立为论文主线。** 更值得先验证的是：如何避免候选融合丢掉语义检索已找到的记录，以及如何围绕原 claim 保留时间、状态和支持范围所需的证据。Judge 对“部分支持、计划/完成、持续/全面”的判断仍是重要瓶颈。

本任务已完成执行与自查，等待独立复核。预算规则已按用户最新要求改为**任务预估总费用不超过 40 元直接执行**；本轮实际 usage 估算 **¥4.1528**，不是已核对账单。

## 1. 实际比较了什么

沿 003 冻结顺序使用此前未逐例分析的第 13–18 名开发患者：84454、67117、71743、72844、93788、26858。从 494 条有效 atomic claims 按固定患者/作者/类别哈希规则选 144 条，每患者每作者 12 条。LLM 的 S/NS/NA 为 **67/4/1**，human 为 **41/13/18**；这是少数类加密的小样本，不是自然分布，更不是保留测试成绩。

三臂共用同患者、目标住院日期范围内的 **941 个可追溯 EHR 片段（166 份记录）**，排除出院小结。基础检索均为 BM25＋BGE-M3 dense；不是原 VeriFact 索引的等价复现。

| 方法 | 查询差异 |
| --- | --- |
| direct：主要对照 | 原 atomic claim |
| simple：无 LLM 的来源扩展 | 原 claim＋字面来源句＋parent 及其前 240 字符 |
| planner：候选方法 | 原 claim＋LLM 生成的最多两条短查询 |

Planner 只看原 claim 和未核验的局部来源，区分原命题要求、来源线索、术语推测；不看 EHR 或 GT。实际使用的是一次性查询规划，不是多轮智能体。每个查询的 BM25/dense 各取前 80，RRF 融合后每臂最多 **48 个候选**；多查询保留 direct 前 8 个，再按原查询一半、扩展查询合计一半权重融合。

三臂候选并集统一用 **原 claim** 调 BGE reranker，各臂限制在自己的候选中选择。最终最多 16 个完整片段、每 note 最多 2 个、正文及单条记录头共 8,000 字符；不截断入选片段，不按零命中臂清空其他臂。Judge 只收到原 claim 和实际 EHR，使用同一 DeepSeek-V4-Flash、004 普通 structured、temperature=0、thinking=false、max_tokens=2048。平均完整输入为 **2,985/2,975/2,984 tokens**，上限相同、实际长度近似可比。[冻结协议](../execution_protocol_001.md)

432 个逻辑判断按完整 body 预先去重，实际生成 299 次，另有 12 次固定重复诊断，共 **311 次，全部有效**。复用省去 133 次生成；78 条 planner/direct 输入完全相同，直接共享结果。12 次重复均未改标签，但不足以证明模型没有波动。93 个回答有结构、词数或引用编号等合规诊断，按预设保留合法标签；不能由格式偏离推断没有进行相应判断。

## 4. 限制：不能把当前结果直接推广为 planner 无效

**接口损耗很大且不均衡。** 144 个原计划全部给出两条查询；100 个通过格式检查，44 个按预设退回 direct。其中 28 个仅因引句空白/换行差异被拒绝，另有额外字段或其他问题。实际使用计划的是 LLM **65/72**、human **35/72**。主指标保留全部样本，但这一差异与类别构成共同限制作者间解释；不能由退回推断没有理解来源，也不事后放宽解析、重跑或只报成功子集。

**来源限定仍可能改变搜索范围。** P130 将来源的 POD5 写进需求和查询；P097 查询加入 EVD 撤除后，而原 claim 未写该条件，最终 reference 恰好没变。这是可见范围风险，不是已经证明的错误因果。P030 的 1500mL 和 P142 的 POD1 则只是原表述换算，不能把所有新数字都算作幻觉。[范围阅读](../../../tasks/008_retrieval_planning/planner_scope_notes.json)

**可检索记录本身也有限。** 患者 84454 的本住院原 release 记录只有 5-25 至 5-28，出院为 6-02；P097/P100 来源描述了 5-30 附近事件。换查询不能凭空补出缺失时段的记录，更不能把 BHC 变成证据。此处只作元数据可用性诊断，不对临床事件重新裁决。[记录日期覆盖](diagnostics_001/corpus_availability.json)

只有六患者、一次性规划、固定容量和一个服务别名；没有医生 gold evidence、不可变权重版本或针对每个翻转的消融。12 次重复无翻转只减轻、不能消除波动顾虑。以上解释均须与直接观察区分。

## 5. 与已有研究的关系及下一步

[Query2doc](https://aclanthology.org/2023.emnlp-main.585/)和[Query Rewriting](https://aclanthology.org/2023.emnlp-main.322/)已研究生成式查询扩展；[RARR](https://aclanthology.org/2023.acl-long.910/)已生成核验问题并找证据；医学领域的[Step-by-Step FV](https://aclanthology.org/2025.naacl-short.68/)也有逐步提问，但主要评一般医学/健康声明的二分类，排除 NEI。[FIRE](https://aclanthology.org/2025.findings-naacl.158/)进一步讨论迭代检索和成本。008 不能把规划本身作为创新；区别在个人 EHR、原医生独立命题标签、来源不可信及患者事件/支持范围约束。实际阅读范围和差异见 [定向文献记录](../../../tasks/008_retrieval_planning/research_notes.md)。

**建议暂停扩大通用 planner，优先验证候选融合与证据组织。** 保留本次 direct 作为共同对照，先离线检查保留 dense 高排记录、避免只含标题的片段、按原 claim 的时间/数量/状态需求选择互补证据。下一次小规模受控实验可固定候选来源、模型和最终 token 上限，比较当前单段相关性排序与保留原记录邻接/时间覆盖的选择；同时报告是否真补足证据，以及 Judge 是否仍把计划当完成或错误宣称缺证。只有新开发患者上出现证据和标签的一致改善，才值得扩大。

仅修 planner 的空白容忍可减少接口损耗，属于必要实现修正，不是论文贡献；若继续用 planner，应先修此问题再重新冻结方案，但本轮不改历史查询和回答。当前支持“局部补充有用”，不支持“LLM 规划已有独立稳定优势”，更不支持靠扩大调用或换模型直接解决问题。
