2026-09-24。**结论：已经证明“存在可救回病例”，尚未证明能在不知道正确答案时可靠地识别该救谁、怎么救。近期失败同时包含方法本身无增量和上游分数与旧后处理不兼容，不能用一个原因概括。当前没有足够证据升级默认系统，也没有依据继续轮换小技巧。**

## 1. 本轮究竟核对了什么

071–075的原生请求、回执和保存预测共重建**1164条逻辑方案输出、1159份不同成功回答、264条不同命题、16名不同评价患者**。360个阶段病例记录不能当作360个独立命题：071和072使用同96条。073以后相同请求跨臂共享回答，因此逻辑输出数也不等于API调用数。

逐条校验实际请求体、模型返回ID、命题和reference、患者/作者/医生标签、raw、scores、PriorG及无效回退；071六条通信恢复按原映射绑定成功回执，没有重发。8条逻辑输出核心无效，完整系统沿用各任务冻结fallback，绝不把fallback算成上游方法成功。全部1156条有效逻辑输出中，**raw verdict与未调整scores最大类完全一致**，此次没有“文字判一类、原始最高分却是另一类”的混淆。

保留两种分母：原报告的多臂共同有效raw成绩用于复现；方法两两归因用这两臂共同有效ID。后者有时比原报告多1–2条，不能直接混用。完整系统另包括fallback。所有正式比较使用项目公共evaluate/paired_compare及1000次患者bootstrap；检查12004项通过，检查条数不代表独立实验数量。独立审计未执行。

## 2. 当前系统的完整逻辑与成绩定位

研究评测以已有医生标签的claim为单位；整篇文档输入、拆分、问题定位是应用目标，不能拿当前claim级成绩直接宣称整篇文档系统已经完成验证。

当前实验链路为：已知患者和合格EHR语料 → 冻结检索的48候选与BGE重排 → final pack → T-S thinking-high → Frozen PriorG → 最终三分类标签。

- **前处理：** 原claim分别做BM25词面与BGE-M3稠密检索，按dense、BM25交替保留不重复ID至48候选，再由原claim做BGE rerank。按rerank次序选段，去精确重复、每note最多2段、最多16段、8000字符预算（具体记录头计入方式沿用冻结packer）；附证据编号/时间信息成为实际reference。C48指候选规模，不意味着Judge实际看到了48段。071–075直接复用冻结reference，不重新检索或打包。[009链路来源](../009_retrieval_baselines/report.md)、[042打包核对](../042_coverage_aware_evidence_packing/report.md)
- **推理：** 阿里云`deepseek-v4-flash-0731`，thinking-high scoring。默认B无示例；同一次回答生成核验检查、reason、raw verdict和三类分数。提示本来已要求核查完整命题、支持与反对证据，不能把追加类似文字本身当新信息。
- **后处理：** 对三类分数做冻结G偏置和先验比例修正后取最大类。S=Supported，NS=Not Supported，NA=Not Addressed。分数变换不重写原reason；最终标签改变并不等于模型重新建立了证据解释。
- **无效输出：** 按任务冻结规则回退已有U2预测；071/072来源053，073–075来源034。它是完整实验系统的备用结果，不是新示例的推理收益。

053是当前链路的development依据：T-S+PriorG **201/240、MCC 0.5607、false-S 8**，相对同批T-S+U2 **194/240**为7救回、0伤害；PA和MCC患者区间均为正。但同批旧U2/Gate均203/240，因此PriorG是有较好类别/风险权衡的当前参照，**不是所有指标的全局冠军**。它没有继承036的最终测试资格或分数。[053报告](../053_thinking_prior_validation/report.md)

## 3. Oracle空间为什么没有直接变成收益

066同240条：当前201正确，已有输出中按GT挑选的Reasoning Oracle 215，GT知情证据包212，combined 223。39个原错误中，推理侧救14、证据侧救11、重叠3，合并救22；其余17未救。

这些数字证明“现有方案附近存在更好的逐例输出”，不等于存在一个部署时可用的统一规则。Reasoning Oracle在不同Judge、raw和后处理输出间按正确答案选择，不能把14条全称为纯LLM推理算法可修复错误。证据Oracle的11条也包含已有信息聚焦及C48外证据；C48→final pack确有信息丢失，但不是所有错误的唯一瓶颈。[066报告](../066_oracle_headroom/report.md)

缺失的关键环节是**可识别的效用信号**：系统在看不到GT时，能否预测“加/删哪段会纠错，又不会损伤本来正确的病例”。相关性、覆盖率、相似度和解释更详细都没有自动提供这个信号。不存在可靠信号时，换selector或prompt只是移动判定边界。

前处理证据要分开：

| 证据 | 实际说明 | 不能说明 |
|---|---|---|
| 043：条件筛选病例raw净+13 | 已经定位的关键证据能对原Judge有用 | GT盲端到端选择器有效；该队列来自reserved后的机制分析 |
| 044：687共同有效，learned仅1救回0伤害 | 存在正例，但可学习监督稀疏 | 学到可泛化效用模型 |
| 067 v1 | 原包映射失效，所谓补证据实际大量缩包 | 不能作为“保守追加失败”的有效检验 |
| 068 v2：236条raw177→181，final198→200 | raw有4条救回；其中3条在27条定向重复中同病例重现 | 原2条final救回均未重现；增删混合且未建立盲选择规则 |
| 069：10个oracle修复病例 | 稳定只增2、只删1、组合1；原包重复本身3条改对 | 未执行20条盲验证与正确病例保护，不能声称部署改善 |

因此停止当前packing技巧与效用selector开发有依据；也不能把067实现错误和全部前处理潜力一起判死刑。076只复算068既有台账，不冒充对067冲突来源的独立审计。[067更正](../069_final_pack_controlled_repair/067_correction.md)、[068重算](packing_v2_reconstruction.json)、[069报告](../069_final_pack_controlled_repair/report.md)

070进一步给出保护集反例：在237共同有效条目上，N/T/Q替换相对G分别救回/伤害9/28、1/19、11/23。**Oracle只数能救哪些错；真实方法还要承担新造出的错。**这比“headroom很大”更直接决定是否值得继续。[070报告](../070_fixed_evidence_reasoning_diagnosis/report.md)

## 4. 071–075的收益到底发生在哪一层

定义“后处理净作用”为同一组ID上final正确数减raw正确数。于是：

`共同有效final净差 = raw净差 + 候选后处理净作用 − 基线后处理净作用`

`完整系统final净差 = 共同有效final净差 + 涉及无效/回退病例的净差`

这是可验证的计数恒等式，只解释输出结果，不证明模型内部因果机制；MCC不能按这个公式相加。下表均为候选减对照，正数表示多答对。

|---|---:|---:|---:|---:|---:|
| 071 F4−B | 95 | +3 | +2 | 0 | +5 |
| 072探索 F4−B | 36 | 0 | 0 | 0 | 0 |
| 072确认 F4−B | 59 | +2 | +1 | 0 | +3 |
| 072确认 D4−F4 | 58 | 0 | +1 | 0 | +1 |
| 073探索 F4−B | 35 | +1 | 0 | +1 | +2 |

| 074 H6−B | 36 | −4 | +3 | 0 | −1 |

| 075 F4−B | 36 | +2 | −6 | 0 | −4 |

B无示例；F4固定4例；D4动态4例；H6固定4+动态2；R4在F4上加研究者撰写批注。全比较及类别/作者分层见[配对分解](paired_decomposition.json)，完整逐阶段表见[数字附录](numeric_appendix.md)。

三个会改变判断的纠正：

1. **073探索的F4净+2不能全归功于示例。**其中1条F4输出截断后回退历史U2而判对。排除此项，真实有效输出净+1；随后60条确认最终净0。
2. **072动态超过静态的确认净+1不是动态选择的实证收益。**18条两臂请求体相同、分别调用的病例贡献全部+1；真正更换示例的42条净0。这里不是要求重跑，而是正确利用已有输入指纹排除误归因。
3. **075既有后处理兼容问题，也有推理损伤。**F4 raw比B多对2条，PriorG对B净+3、对F4净−3，最终反而少对4条。批注R4比F4最终多对1条，但raw为0救回2伤害；不是批注教会了更好的推理。

075的两条raw伤害均为同一患者的真S：一条把有心脏会诊/用药的“密切监测和管理”要求成必须有近似字面表述；另一条将“术后在ICU处理贫血”读成“因贫血才住ICU”。这是实际输出中可观察的解释尺度变化，不能升级成医学新裁决，也不能由两例断言批注普遍过严。[075病例核对](../075_annotated_static_examples/case_interpretation.md)

## 5. PriorG是不是掩盖了上游改善

**局部确实如此，但它不是所有失败的共同原因。**

按053冻结参数，忽略共同归一化因子，PriorG相当于将S/NS/NA分数乘以约**2.7397 / 0.2208 / 0.3675**。相对NS，S被放大**12.408倍**、NA为1.665倍。以S/NS/NA为5/90/5时仍判NS，而10/85/5已会变成S；raw标签虽相同，少量分数变化也能触发final翻转。这是一个较强的类别偏置修正，不能把模型自报分数当成已验证的临床概率。[冻结变换](fixed_transform.json)

固定消融表明：本轮有效输出raw和score argmax全部一致；仅加原G的小偏置也没有改变raw标签。完整PriorG相对“只做先验比修正”只在3条逻辑输出上改变标签（2个不同claim），均少答对1条。**大部分改判来自先验比修正。**这只是定位作用来源，不据此选择“去掉G”的新赢家：同一个错误claim在071/072出现两次，不是三项独立证据。[固定消融](fixed_postprocessing_ablation.json)

也不能由075反推PriorG整体无效。它在053有开发确认，071对F4还放大了正向净差；074 H6的raw已经比B少对4条，PriorG反而补回其中部分差距。当前准确结论是：**既有后处理参数的收益不保证跨prompt/示例配置迁移；输出分数变化和raw变化须分开评价。**

重新校准能否获得新收益尚未检验，更没有“校准必能救活F4”的证据。以这批已反复查看的病例重新找最佳阈值会再引入方法选择偏差。本轮不拟合、不扫阈值，后处理继续冻结。

## 7. 已定位、可识别、可学习分别到哪一步

| 层面 | 已有证据 | 仍缺什么 | 当前决定 |
|---|---|---|---|
| final pack | 候选到实际输入会丢关键片段；部分定向补证据确有作用 | GT盲逐例效用信号及正确病例保护；相关性不等于有用 | 暂停当前selector路线 |
| 动态示例 | 词面/语义相似并未形成相对F4稳定收益 | claim与EHR支持关系是否可匹配；目前多为claim相似度 | 停止D4/L4/M4/H6当前版本 |
| 静态示例 | 有局部raw阳性，综合净差小且主要在human | 更广病例上的类别保护与明确增量 | 保留对照，停止继续微调静态例子 |
| 精细批注 | 分数/解释尺度会变；075 raw反降 | 正确关系判定改善，而非更严/更松 | 停止当前R4 |
| 上游与PriorG兼容 | 076已经证明差异可定位到固定变换 | 新prompt下可迁移、患者隔离的校准收益 | 不把诊断当新方法；暂不重训 |
| 无标签/少标签适应 | 054–064部分模拟可行，实际双向收益未闭合 | 可靠区分类别比例变化与条件漂移 | 不作为下一轮脱困方案 |

“尚未可学习”不等于数学上不可学习，而是当前规模、标签与特征还没给出足够证据。特别是只有命题级医生标签，没有新的医生证据充分性标注，不能把自动审计的quote/reason直接当新的监督真值。

我们此前把“直觉合理、会影响输出”过快升级成“值得做下一方法”，这是需要纠正的研究决策。今后恢复某一路线至少应有现成数据展示：与目标错误对应的部署可见信号、跨病例可复用的正例，以及没有同等规模的镜像损失。无需先全量重跑成功请求，但也不能仅凭oracle或两个成功案例连续扩展方法。

## 8. 论文怎样收束才清楚

目前最可辩护的主线是：**临床事实核验中，标签一致率、错误支持风险与证据/解释一致性并不自动同步改善。**三阶段研究服务于这个问题，不必强行让前处理、LLM和后处理各有一个成功模块。

建议正文保留三组问题：

1. **判定边界怎样改变准确率与错误支持风险？** 以034–036的同队列比较与冻结最终评价为主。036共同有效3571条：U0→U2正确2731→2908，但false-S 81→204；Gate A相对U2少22正确、少63个false-S。标准M/V正确2999/3004，更高但false-S 251/254，不能藏起来宣称λ2最优。
2. **标签改对是否等于证据与解释也改好？** 038–043给出事后机制证据；053说明thinking+PriorG在development上的类别权衡。038–043含reserved事后诊断，必须与036事前冻结测试分栏，不能合并成新的独立确认。
3. **为什么上游可见空间难以转换为部署收益？** 066与070说明oracle选择优势和保护集损失；076用少量代表性对照区分raw、固定变换与回退。完整负结果放附录，不按任务号写成逐次试错日记。

036的核心结论可以支撑边界/风险实证研究；不能声称当前PriorG已做最终确认、标准校准是新算法、临床安全已验证或全面胜过原VeriFact。自动解释审计也不是医生新增裁决。是否足以满足具体毕业/投稿标准取决于导师要求，076不能代替这一判断。[036报告](../036_final_validation/report.md)、[历史写作交接](../036_final_validation/paper_handoff.md)

**下一步优先整理论文主表、方法定义和上述三条研究问题，不自动启动077。**当前不推荐再开动态例子、批注或packing微调；若必须追求新上游方法贡献，应先改变证据条件（新的可靠监督/明确可识别信号），而不是继续换相似度权重或措辞。此结论不是“所有潜力不存在”，而是现有证据下继续投入这些版本的预期回报很低。
